## 数据路径与生产约束

```mermaid
flowchart LR
    A[合成订单 JSON] --> B[契约校验]
    B --> C[ODS 原始归档]
    C --> D[DWD 订单版本化入账]
    D --> E[ADS 站点日指标视图]
    E --> F[FastAPI 查询]
```

- **接入与发布**。生产按订单、遥测、站点与价格、气象分开接入。ODS 保留经字段白名单或必要脱敏之后的原始载荷。ODS 和 Kafka 之间需要持久发布状态及可重试补投。轮询降级使用只读副本、`(updated_at, order_id)` 游标、15 分钟回看和日对账，另行确认硬删除的捕获机制。
- **订单与财务**。生产幂等沿用业务键和版本。当前分别汇总订单携带的电费与服务费，金额用整数分、电量用整数 Wh。分时收费明细需要费率版本、计费分段电量和舍入规则，由财务确认后实现。演示采用结束时刻按上海时区归日。
- **实时与回填**。采用正文及 S2 的 5 分钟事件时间窗口、2 小时水位。设备时钟偏移隔离和未来时间拦截先于水位更新。实时暂估与批量正式指标写入独立表，语义层按窗口键和正式覆盖截止点选取结果。同一窗口只计一份，迟到数据走可追溯回填。Kafka 生产目标为三副本、最少两个同步副本及幂等发送，Spark Checkpoint 放可靠共享存储。
- **特征与查询**。分层输出由语义层统一发布。特征查询以 as-of 时点切片，气象使用该时点可获得的预报快照。业务对账使用统一冻结快照，单独记录迟到与补数调整。

## 实施顺序

1. 将合成契约映射到内部批准的脱敏样本。先确认 C-1、C-2、C-9、C-11，尤其是订单变更语义、分时电量和退款归属。
2. 实装采集、PostgreSQL 迁移、对象归档和日对账，覆盖版本冲突、重跑与断点续跑。气象接口在 C-10 商业授权确定后纳入。
3. 上 Kafka 与 Spark 联调，验证重复、迟到、水位、设备时钟、回填竞争、故障恢复。验收清单需核对正文所列 S1–S9 与基础设施 I1/I2。
4. 对接内部鉴权、指标字典、看板和特征，按项目验收工况实测时效、容量、可用性及 RTO/RPO。

当前版本验证 SQLite 与 PostgreSQL 的合成订单链路，覆盖独立金额汇总、旧版本回放、拒绝非法输入、跨午夜归属及 PostgreSQL 并发写入、归档导出和日对账差异。真实计费源适配、对象存储、流任务、正式分时计费、生产部署和真实数据对账留待后续迭代。

## 计费源 V1.0 联调契约

收到经批准用于联调的 JSON Schema 和字段字典后，新增独立适配层 `cdp.billing`。先按随镜像发布的源 Schema 检查载荷，再校验 UTC、事件时间取结束时间、整数分勾稽及可用分时数组的电量与费用总和。已完成订单可投影到现有沙箱模型，手机号、车牌和用户散列均不进入该投影。校验入口 `python -m cdp.billing <脱敏文件>` 只返回状态和能否投影，无数据库写入。

源 Schema 与字典存在需要用样例核实的差异。Schema 要求充电中也提供结束时间，且允许省略事件时间、占位费、抵扣和币种。适配层当前按结束时间推导缺失的事件时间，金额默认 0，币种默认 CNY。源字典的版本顺序包含同版本按较新 `updated_at` 决胜，现有 0.1 存储只按版本处理。V1 明细已按源版本及更新时间持久化生命周期状态。退款对账还需明确冲减金额和业务日归属。

V1 开发明细表 `dwd_billing_order_v1` 可通过 `python -m cdp.billing_ledger <合成事件文件>...` 写入。每笔订单保留当前状态、金额组件和关键业务字段，按版本优先、同版本按 UTC 更新时间排序。完全重复跳过，同键同版本同时间的业务内容冲突显式报错。当前快照与新增历史记录在同一事务提交。历史保存每次成功入账的版本及其规范化分时明细，忽略旧版本和完全重复重放。旧库迁移只回填当时的当前快照，其分时明细标记为未知。原始载荷和个人标识散列均不进入 V1 明细。现有演示日指标继续查询自己的明细表。退款冲减日期和金额仍待业务口径确认。

用 `python -m cdp.billing_ledger --history <订单号>` 查询 V1 版本历史。新事件的空分时数组为 `[]`，历史迁移带来的未知分时信息为 `null`。

V1 增量入口已通过合成 SQLite 源接至 V1 明细。分页用更新时间、订单键和版本排序，并在写入前核对索引键和 JSON 载荷。V1 与旧演示使用独立检查点，复用同一轮询与回填流程。

合成 V1 链路已增加单节点 Kafka 4.2 KRaft 发布。已入账历史作为待发布来源，收到 Kafka 确认后在 PostgreSQL 记录分区与偏移。传输语义为至少一次，消息包含可跨重试使用的 `event_id`，并按订单号分区。当前沙箱逐条确认，每条发布会短暂占用该订单的写锁。消费者持久去重、流聚合及多副本故障演练属于后续生产链路。

Kafka 开发消费者已实现数据库先提交、消费偏移后提交，基于 `event_id` 持久去重，并按订单结束时间提供 5 分钟 UTC 生命周期事件窗口。窗口可受历史重放更新。开发消费者已持久化两小时水位、迟到事件和未来时间隔离记录，并支持按日手动回填。生产监控和调度仍属于后续阶段。

Spark 4.2 接入已实现 Kafka Structured Streaming 来源与持久 checkpoint。微批按分区和偏移排序，写入既有 PostgreSQL 事件持久化规则并保留事件级幂等。当前使用 Compose 本地双线程和单 driver 回调，适用于开发重启与重放演练。生产分布式聚合、共享存储和调度仍需验证。

开发运维层提供 Prometheus 抓取与持久化指标查询，覆盖待发布、迟到、隔离、水位和最近 Spark 落库回调。版本 0.9 的指标查询按数据库现存记录聚合，适用于开发数据量；生产高频采样应采用增量计量或独立统计存储。告警演练规则以沙箱阈值运行，生产通知、SLO 和权限配置需单独接入。

S3 崩溃重跑已有可执行开发演练。脚本在临时 PostgreSQL 中暂停第二条写入，观察首条已提交后终止 Spark，再沿用同一 checkpoint 重启。验收检查包含回放结果、落库行数和窗口查询。覆盖开发环境的部分微批提交，真实吞吐和生产故障目标需另行实测。

S4 字段变更已有端到端演练。增量契约拒绝可持久记录到来源质量状态，并由 Prometheus 告警。修复后从上次成功检查点重读，已入账版本按原幂等规则识别重复。质量记录覆盖业务载荷拒绝，网络故障、数据库不可用和正式通知链路仍需单独监测。

开发驾驶舱通过 FastAPI 提供同源静态页面和只读查询，复用站点日报、窗口与采集质量 API。以 Asia/Shanghai 归集展示日期和小时，底层窗口保留 UTC。驾驶舱暂按开发沙箱权限运行，生产身份认证和正式财务指标仍待接入。

站点特征任务已支持指定历史时点，使用订单源更新时间和平台入账可用时间双约束。可用时间在明细事务成功后登记；缺少此证据的历史版本不参与特征计算。每笔取当时可见最新版本，再生成过去 24 小时的已完成订单数和电量。训练样本物化仍需后续接入。

天气特征支持离线预报快照及下一 UTC 整点的时点关联，按源发布时间和平台可用时间取可见的最新版本。实况不进入预报契约，缺失值显式保留。实际天气供应商和站点映射待联调。

充电量预测首版采用 24 小时持续性基线，复用订单时点特征。离线回测使用目标结束时可见的目标区间实绩，报告配对覆盖、MAE 和 WAPE。已补入但在目标结束时不可见的订单不会改写该回测结果。后续训练和预测可将此版本作为可解释的对照。

驾驶舱已接入只读站点预测接口，默认以当前时点生成 24 小时持续性预测。日报日期与预测切点独立，预测结果展示目标时段及缺数状态。

合成计费链路新增可选的周期任务，按单来源串行运行增量采集和有界 Kafka 发布。任务复用现有检查点及质量状态，受阻时跳过发布，后续周期自动重试。此开发任务与生产 Airflow 编排、告警通知和多源调度独立。

开发 Compose 的 pipeline profile 可同时运行采集发布器与 Spark 持续消费服务。Spark 使用同一 PostgreSQL 数据库内按配置路径区分的会话租约，避免重复持有 checkpoint，微批前检查租约连接。该机制用于单套开发 Compose 的路径约定；生产共享 checkpoint、跨环境租约设计和调度仍需单独验证。

V1 新历史版本增加规范化归档证据。归档正文是满足最小必要字段的事件载荷，依摘要落本地卷，数据库在接受历史的同一事务记录摘要。Kafka 发布带证据的版本前验证该文件；原始载荷和散列身份字段仍不保存。旧版本如无归档证据会标记为旧库记录。对象存储迁移和跨环境备份恢复仍需后续验证。

V1 本地归档增加按订单备份和恢复的 S3 兼容命令。上传使用条件写入，并在上传或检测到已有对象后读取验证；恢复先验证远端字节，仅补齐缺失的本地文件。数据库摘要关联仍是恢复索引。开发使用隔离的 SeaweedFS，生产对象存储凭据、备份调度、保留策略和全库恢复演练仍需落地。

开发环境支持 PostgreSQL 逻辑备份与 V1 全量归档联合恢复。Bulk 命令使用版本键分页，返回归档缺失或完整性失败的汇总。演练对目标库和归档文件独立核验。生产备份需确保写入静止或使用同一时点的一致性方案，并单独覆盖 Kafka 与 Spark 状态。

联合恢复演练已包含采集检查点。源标识和 UTC 水位保存在可校验的逻辑快照中，恢复到空数据目录后验证新增版本从原水位继续采集。目标存在不同进度时拒绝恢复。

Kafka 历史可由已校验的 V1 归档重建到独立恢复主题。进度按 Kafka 集群与恢复主题记录，保留原主题和原发布标记。演练覆盖小批次续跑和内容逐字节比对。生产消费者切换、跨地域 Kafka 恢复和 Spark checkpoint 迁移仍需验证。

开发 CLI 支持消费独立 Kafka 恢复主题，按恢复运行和目标数据集隔离消费组。演练覆盖从已处理的目标去重重放，以及空目标恢复并续读。生产切换仍需核对全量结果、分区乱序下的迟到回填与 Spark checkpoint 策略。

Spark 恢复模式绑定独立主题，并按 Kafka 集群、运行和目标数据集派生 checkpoint。目标库可以从恢复主题重新物化窗口，并在其独立 checkpoint 上增量续读。原 checkpoint 和生产切换策略保持独立，跨环境共享存储尚需演练。

恢复验收增加只读窗口比对，覆盖 UTC 日期范围内正常事件的标识与载荷摘要、窗口聚合和相关待回填状态。无数据、来源或目标存在待补数据、窗口不一致、事件摘要不一致均不通过。目标平台上线还需核对财务指标和部署切换。

恢复验收的 `--stream-state` 模式增加整条流的水位与隔离记录摘要比对。日期范围仍用于窗口检查，隔离与水位以完整流状态为准。验收只读，隔离记录补齐和生产切换独立执行。

流状态快照支持带摘要导出与恢复。导出在流写锁内采集完整事件指纹、水位及隔离元数据。恢复验证目标事件及待回填状态与快照一致，并在一个事务内补齐缺失隔离记录和水位。隔离冲突或事件指纹不一致时中止。

开发驾驶舱可选启用只读 Token 登录。服务只配置高熵令牌的摘要，按恒定时间比较，在启用时为受保护资源记录访问审计。页面及查询保持同源。正式身份提供方、站点级权限、生产 TLS 与集中审计仍待集成。

驾驶舱只读账户支持可选站点范围。数据 API 在响应前按站点过滤，站点级账户不能读取全局采集状态。范围为空时无可见站点。权限目前由应用层实现，生产数据库权限和身份提供方仍待接入。

PostgreSQL 开发部署可将 API 查询与迁移、写入账号分离。只读角色按 API 使用的关系授权，API 启动时校验公共业务 schema 的写入权限，并使用只读归档挂载。连接使用只读事务，启动和就绪检查复用授权清单校验全部查询关系。站点级授权继续由应用层执行，生产统一身份和服务账号管理仍待接入。
